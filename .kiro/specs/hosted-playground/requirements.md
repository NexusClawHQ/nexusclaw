# Requirements — Hosted Playground（访客 60 秒治理闭环体验）

> Spec ID: `hosted-playground`
> 状态: **Draft — Mockup 评审中**
> 上游: `product-showcase-dashboard`（复用其读模型与设计系统）、`console-experience-byo-model`（BYO 在 playground 中被强制禁用）
> 定位宣言: GitHub 访客 → 评估者漏斗里最陡的一跳是"装 Docker 起栈"。playground 让访客**不注册、不安装**，60 秒内在真实治理运行时上跑完 L1/L3 闭环并查看审计链——OPA Playground 路线的社区版落地。

---

## 1. 背景与动机

案例研究结论（2026-08-18）：OPA 无产品 UI 仍毕业，但做了 Rego Playground——60 秒可体验的网页入口是库优先项目的转化关键。当前社区版两个入口都有门槛：`/app` 需要登录态与本地栈，`/console` 同样需要自托管。漏斗数据（假设，待托管后验证）：仓库访问 → star 转化尚可，star → 本地起栈转化极低。

**真实性红线延续**：playground 跑的是**真实 community runtime**（确定性剧本、真实权限/护栏/审批/审计管线），不是前端录像模拟。若实现中引入任何"录制的假运行"，必须显式标注为 replay 且不得冒充实况——本 spec v1 不做 replay。

## 2. 产品形态

```
访客打开 play 页（静态托管或同域 /playground）
   │ ① 点击「运行治理闭环」（唯一主按钮，无注册）
   │ ② 后端签发匿名 playground 会话（独立临时 workspace + 短期 JWT）
   │ ③ 确定性剧本执行：L1 查询放行 → L3 发信暂停 → 访客自己批准 → 完成
   │ ④ 实时时间轴展示各阶段；完成后展开完整审计链（与 /app 同读模型）
   ▼ ⑤ 转化 CTA：GitHub 仓库 / 自托管三行命令 / 商业版
会话 30 分钟无活动自动回收（数据删除）
```

## 3. 用户故事与验收标准（EARS）

### US-1 访客 60 秒闭环（GitHub 访客）

- **AC-1.1 零门槛进入**：当访客打开 playground 页时，系统应当无需注册、登录或安装即可展示可运行的闭环入口，从打开页面到提交运行的交互步骤不超过 1 次。
- **AC-1.2 真实运行时**：当访客运行闭环时，系统应当在真实 community runtime 上执行确定性剧本（真实权限/护栏/审批/审计管线），并在实时时间轴上呈现 L1 放行、L3 暂停、批准恢复各阶段。
- **AC-1.3 审计链可见**：当闭环完成时，系统应当向访客展示完整审计链（execution → ReAct 步骤 → 工具调用 → 事件流），数据来自同一读模型，与 `/app` 一致。
- **AC-1.4 访客即审批人**：当 L3 暂停发生时，系统应当允许该会话的访客在自己作用域内完成批准/拒绝，体验人工治理门。
- **AC-1.5 双语**：playground 界面应当提供 zh/en 双语，切换即时生效。

### US-2 会话隔离与防滥用（运营者/安全）

- **AC-2.1 会话隔离**：当两个访客同时使用 playground 时，系统应当为每个会话提供独立的临时 workspace，执行、审批与审计数据互不可见。
- **AC-2.2 自动回收**：当会话空闲超过 30 分钟（可配置）时，系统应当删除该会话的 workspace 及全部关联数据；被回收会话的令牌立即失效。
- **AC-2.3 速率限制**：当同一 IP 的请求超过阈值时，系统应当限流（会话创建 ≤3/小时、执行 ≤20/小时，内存令牌桶，零依赖），超限返回明确的 429 文案。
- **AC-2.4 凭证隔离**：playground 模式启动时，系统应当强制禁用 BYO（`COMMUNITY_LLM_*` 即使设置也拒绝启用或拒绝启动），会话内不存在任何密钥、真实外发通道或付费资源。
- **AC-2.5 最小权限**：匿名 principal 应当只具备 demo agent 执行、本会话审批、本会话审计读取三项能力，不得触达其他 workspace 或任何管理面。
- **AC-2.6 工具面封闭**：playground workspace 的工具集应当仅含确定性 dry-run 工具（查询/发信均为干跑，不产生真实副作用）。

### US-3 部署形态（自托管者）

- **AC-3.1 一键启用**：playground 应当作为 compose profile（`--profile playground`）提供，默认不启用；启用后与其他服务共用栈但环境变量隔离。
- **AC-3.2 文档**：README 应当包含自托管 playground 的启用说明与安全注意事项（公开端口、限流参数、回收窗口）。
- **AC-3.3 范围声明**：官方托管实例（play.nexusclaw.cn 等）是运营决策，不在本 spec 交付范围；本 spec 交付可自托管的全部能力。

### US-4 转化（增长）

- **AC-4.1 完成 CTA**：闭环完成视图应当提供三个出口——GitHub 仓库、自托管快速开始（三行命令可复制）、商业版了解入口。
- **AC-4.2 失败兜底**：当会话创建或执行失败时，系统应当展示致歉文案 + 本地快速开始降级路径，不留白屏。

### US-5 纪律延续（维护者）

- **AC-5.1 零新依赖**：不新增 npm 依赖；限流用内存实现，页面前端复用零依赖单页形态（同 console 模式）。
- **AC-5.2 门禁保持**：全部既有门禁与测试保持通过；playground 模块有独立单测（会话生命周期、限流、回收、权限收窄）。
- **AC-5.3 边界纪律**：命名与路径避开商业词汇禁则；`packages/shared` 零改动。
- **AC-5.4 守卫延续**：playground 页面遵循 console 同款守卫（零外部资源、textContent-only、COPY 奇偶、稳定状态键）。

## 4. 非目标（明确不做）

- 不做 BYO key 的客户端直连托管（密钥永不上托管服务）。
- 不做注册/账号体系与访客数据留存（会话即焚）。
- 不做 replay 录像模式（v1 只做真实运行）。
- 不做官方实例的运维交付（域名、CDN、监控）。
- 不做 analytics 埋点（零依赖；后续如需自托管计数另行 spec）。

## 5. 依赖与风险

| 风险 | 缓解 |
|---|---|
| 匿名面暴露运行时漏洞 | 最小权限 principal + dry-run 工具 + 限流 + 独立 workspace 隔离；上线前安全自查清单 |
| 会话/数据堆积 | TTL reaper + workspace 级联删除 + 启动时清扫孤儿 |
| 恶意批量会话耗尽 DB | 限流 + 单实例并发会话上限（超出排队文案） |
| 体验与 /app 割裂 | 复用同一读模型与设计令牌；时间轴组件与 console/dashboard 同语言 |
| 60 秒承诺不达 | 闭环为确定性同步剧本，实测目标 ≤20s；60s 为含阅读的体验口径 |
